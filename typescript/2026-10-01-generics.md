# 제네릭(Generics)과 함수 타이핑

## 질문
TypeScript의 제네릭(Generics)이 무엇인지 설명하라. `any`를 쓰는 것과는 뭐가 다른가?
지난주에 작성한 `throttle`/`debounce` 함수에 제네릭을 적용해서 타입을 입혀보라. 요구사항:
- `func`에 어떤 타입의 함수가 와도(인자 개수/타입 상관없이) 타입 안전하게 동작해야 한다
- 반환된 함수를 호출할 때 인자 타입이 원래 함수와 다르면 타입 에러가 나야 한다
- `func`의 반환 타입도 그대로 유지되어야 한다

## 내 답변 (처음 생각)

TypeScript의 제네릭은 타입 안정성을 유지하기 위해서 사용하는 것인데, 코드를 작성할 때 구체적인 타입을 지정하지 않고, 사용하는 시점에 원하는 타입을 전달할 수 있는 것.

`any`를 쓰는 건 모든 타입을 허용한다는 것을 의미하는데, 그렇게 되면 입력한 타입 정보가 사라져 반환값의 타입도 알 수 없기 때문에 잘 사용하지 않음. 그래서 주로 `any` 타입은 사용을 지양하는 편.

```typescript
// throttle
export function throttle<T extends (...args: any[]) => any>(
  func: T,
  limit: number
): (...args: Parameters<T>) => void {
  let inThrottle: boolean = false;

  return function (this: any, ...args: Parameters<T>) {
    if (!inThrottle) {
      func.apply(this, args);
      inThrottle = true;
      setTimeout(() => {
        inThrottle = false;
      }, limit);
    }
  };
}
```

```typescript
// debounce
export function debounce(func: (...args: any[]) => any, wait: number) {
  let timeoutId: any = null;

  return function (this: any, ...args: any[]) {
    if (timeoutId !== null) {
      clearTimeout(timeoutId);
    }

    timeoutId = setTimeout(() => {
      func.apply(this, args);
    }, wait);
  };
}
```

## 보완된 개념

### 개념 설명은 정확함
제네릭이 "사용 시점에 타입이 결정된다"는 핵심, `any`를 지양하는 이유(타입 정보 소실 → 반환 타입도 알 수 없음) 둘 다 맞는 설명이다.

### "제약으로서의 any"는 지양해야 할 any와 다르다
`throttle`에 쓰인 `T extends (...args: any[]) => any`의 `any`는 **제네릭의 상한 제약(upper bound constraint)**으로만 쓰인 것이라, 변수나 매개변수 타입으로 직접 쓰는 `any`와는 성격이 다르다.

- **지양해야 할 any**: 값의 타입 자체를 `any`로 선언 → 타입 정보가 그 자리에서 사라짐
- **제약으로서의 any**: "일단 아무 함수나 받을 수 있다"는 뜻일 뿐, 실제 호출 시점에는 진짜 함수 타입이 `T`로 정확히 추론됨

```typescript
function add(a: number, b: number): number {
  return a + b;
}

const throttledAdd = throttle(add, 300);
throttledAdd(1, 2);      // OK
throttledAdd(1, 'two');  // ❌ Type error: 'string' 형식의 인수는 'number' 형식의 매개변수에 할당될 수 없습니다.
```

`T`가 `add`의 실제 타입 `(a: number, b: number) => number`로 추론되고, `Parameters<T>`가 거기서 매개변수 타입만 뽑아내기 때문에 타입 정보가 전혀 안 사라진다.

### debounce는 제네릭이 빠져 있었음
`func`와 반환 함수가 둘 다 `any[]`를 받다 보니, 둘 사이에 "같은 함수여야 한다"는 연결고리가 없어서 타입 에러가 나야 할 상황에서도 안 났다.

```typescript
const debouncedAdd = debounce(add, 300);
debouncedAdd(1, 'two'); // 타입 에러 안 남 — 요구사항 2번 위반
```

### 수정된 debounce
```typescript
export function debounce<T extends (...args: any[]) => any>(
  func: T,
  wait: number
): (...args: Parameters<T>) => void {
  let timeoutId: ReturnType<typeof setTimeout> | null = null;

  return function (this: any, ...args: Parameters<T>) {
    if (timeoutId !== null) {
      clearTimeout(timeoutId);
    }

    timeoutId = setTimeout(() => {
      func.apply(this, args);
    }, wait);
  };
}
```

바뀐 부분:
1. `<T extends (...args: any[]) => any>` 추가 + 반환 타입을 `(...args: Parameters<T>) => void`로 명시 — throttle과 동일한 패턴
2. `timeoutId: any` → `ReturnType<typeof setTimeout>` — `setTimeout`의 반환 타입은 브라우저에서는 `number`, Node.js에서는 `NodeJS.Timeout` 객체라 환경마다 다르다. `any`로 퉁치지 않고 `ReturnType<typeof setTimeout>`을 쓰면 환경에 맞는 정확한 타입이 추론된다.

### 세 번째 요구사항(반환 타입 유지)에 대한 메모
throttle/debounce는 호출해도 `func`의 결과를 즉시 돌려주지 않는 구조다 (throttle은 조건에 따라 아예 호출 안 할 수도 있고, debounce는 나중에 비동기로 실행됨). 그래서 반환 타입이 `void`인 게 맞다. `ReturnType<T>`를 억지로 붙이면 실제로는 안 쓰이는 값인데 타입만 있는 척하게 되어 오히려 부정확해진다.

다만 lodash의 `debounce`처럼 "마지막 실행 결과를 캐싱해뒀다가 돌려주는" 버전이라면 그때는 `ReturnType<T> | undefined`로 타이핑하는 게 맞다 — 지금 구현에서는 필요 없음.

## 추가 심화 질문

### Q1. 제약에서 `any[]` 대신 `unknown[]`을 쓰면 안 되나요?
안 된다. `any`를 지양하려고 `unknown`으로 바꾸고 싶어지는데, 실제로 해보면 타입 에러가 난다.

```typescript
function wrap<T extends (...args: unknown[]) => unknown>(f: T) { return f; }

wrap(add);
// ❌ Argument of type '(a: number, b: number) => number' is not assignable
//    to parameter of type '(...args: unknown[]) => unknown'.
```

이유는 **함수 매개변수의 반공변성(contravariance)** 때문이다. `(...args: unknown[]) => unknown`은 "아무 값이나 넣어서 호출해도 되는 함수"라는 뜻이다. 그런데 `add`는 `number`만 받을 수 있으니 그 약속을 지킬 수 없다. 함수 A가 함수 B 자리에 들어가려면, A의 매개변수 타입이 B의 매개변수 타입보다 **넓어야** 한다 (반환 타입은 반대로 좁아야 함).

- `any[]`: 타입 검사를 건너뛰어서 모든 함수를 통과시킨다.
- `never[]`: `never`는 모든 타입의 하위 타입이라, 어떤 매개변수 타입이든 `never`보다는 넓다 → 모든 함수가 통과한다. `any` 없이 쓰고 싶다면 `T extends (...args: never[]) => unknown`이 대안이다.

TypeScript 내장 유틸리티 타입인 `Parameters`, `ReturnType`도 제약에 `(...args: any) => any`를 쓴다.

### Q2. `this: any`도 타입 안전하게 만들 수 있나요?
`ThisParameterType<T>`로 원래 함수에 선언된 `this` 타입을 뽑아서 반환 함수에도 그대로 붙이면 된다.

```typescript
export function debounce<T extends (this: any, ...args: any[]) => any>(
  func: T,
  wait: number
): (this: ThisParameterType<T>, ...args: Parameters<T>) => void {
  let timeoutId: ReturnType<typeof setTimeout> | null = null;

  return function (this: ThisParameterType<T>, ...args: Parameters<T>) {
    if (timeoutId !== null) clearTimeout(timeoutId);
    timeoutId = setTimeout(() => {
      func.apply(this, args);
    }, wait);
  };
}

const counter = {
  count: 0,
  inc: debounce(function (this: { count: number }, n: number) {
    this.count += n;
  }, 300),
};

counter.inc(1);          // OK
const inc = counter.inc;
inc(1);                  // ❌ The 'this' context of type 'void' is not assignable to method's 'this'
```

메서드를 변수로 꺼내서 호출하면 `this`가 사라지는 실수([디바운스 노트](../javascript/2026-09-29-debounce.md)의 this 예시)를 **컴파일 단계에서** 잡아준다. `add`처럼 `this`를 선언하지 않은 함수는 `ThisParameterType`이 `unknown`이 되어 평소처럼 호출할 수 있다.

### Q3. 제네릭 타입은 꼭 명시해야 하나요? `extends`와 `keyof`는 어떻게 같이 쓰나요?
대부분은 **인자로부터 추론**되므로 명시하지 않아도 된다. 추론이 안 되거나 의도와 다를 때만 `first<string>(...)`처럼 직접 넘긴다.

```typescript
function first<T>(arr: T[]): T | undefined {
  return arr[0];
}

const n = first([1, 2, 3]); // T = number로 추론 → n: number | undefined
```

`extends`로 타입 매개변수끼리 관계를 걸 수도 있다. 자주 나오는 예시가 객체의 키로만 접근을 허용하는 함수다.

```typescript
function getProp<T, K extends keyof T>(obj: T, key: K): T[K] {
  return obj[key];
}

const user = { name: 'suki', age: 1 };
getProp(user, 'name');  // 반환 타입: string
getProp(user, 'email'); // ❌ '"email"' 형식의 인수는 '"name" | "age"' 형식의 매개변수에 할당될 수 없습니다.
```

- `K extends keyof T`: `K`는 `T`의 키 중 하나여야 한다는 제약
- `T[K]` (indexed access type): 그 키에 해당하는 값의 타입 → 반환 타입이 키마다 정확해진다

### Q4. `Parameters`와 `ReturnType`을 직접 구현해보라
**조건부 타입(conditional type)**과 `infer`로 만든다. 실제 TypeScript 내장 정의도 이 형태다.

```typescript
type MyParameters<T extends (...args: any) => any> =
  T extends (...args: infer P) => any ? P : never;

type MyReturnType<T extends (...args: any) => any> =
  T extends (...args: any) => infer R ? R : never;

type A = MyParameters<typeof add>; // [a: number, b: number]
type B = MyReturnType<typeof add>; // number
```

- `T extends X ? Y : Z`: `T`가 `X` 형태에 맞으면 `Y`, 아니면 `Z`
- `infer P`: "이 자리에 들어있는 타입을 `P`라는 이름으로 꺼내라"는 뜻. 조건부 타입의 `extends` 절 안에서만 쓸 수 있다.

### Q5. React에서는 제네릭을 어디서 보게 되나요?
- `useState<User | null>(null)`: 초깃값만으로 타입을 추론할 수 없을 때 명시
- `useRef<HTMLInputElement>(null)`: DOM 요소 타입 지정
- **제네릭 컴포넌트**: 아이템 타입에 상관없이 재사용하는 리스트/셀렉트 컴포넌트

```tsx
type ListProps<T> = {
  items: T[];
  renderItem: (item: T) => React.ReactNode;
};

function List<T>({ items, renderItem }: ListProps<T>) {
  return <ul>{items.map((item, i) => <li key={i}>{renderItem(item)}</li>)}</ul>;
}

<List items={[{ id: 1, name: 'a' }]} renderItem={(item) => item.name} />;
// item이 { id: number; name: string }으로 추론됨
```

`.tsx` 파일에서 화살표 함수로 제네릭 컴포넌트를 만들 때는 `<T>`가 JSX 태그로 해석되므로 `<T,>`처럼 쉼표를 붙여야 한다.
