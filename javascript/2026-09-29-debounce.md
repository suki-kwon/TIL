# 디바운스(Debounce) 구현

## 질문
디바운스(debounce) 함수를 직접 구현하라.
- `debounce(fn, delay)` 형태로 호출하면, 마지막 호출 이후 `delay`(ms)가 지나야 `fn`이 실행된다.
- 연속으로 여러 번 호출되면, 이전 타이머는 취소되고 새로 시작된다.
- `fn`에 전달된 인자(arguments)도 그대로 넘겨줘야 한다.
- 왜 이 구현에 클로저가 필요한지도 설명하라.

## 내 답변 (처음 생각)

```js
function debounce(callback, delay) {
  let timer = null;
  return (...args) => {
    if (timer) clearTimeout(timer);
    timer = setTimeout(() => {
      callback(...args);
    }, delay);
  };
}
```

- 클로저가 필요한 이유: 디바운스는 이전 타이머를 취소해야 하기 때문일 것 같음 (`timer` 변수를 호출 사이에 계속 참조해야 해서)

## 보완된 개념

### 기본 구현 검증
요구사항 세 가지(타이머 취소, 재시작, 인자 전달)를 모두 충족한 정확한 구현이었다.

```js
const log = debounce((msg) => console.log(msg), 300);
log('a');
log('b');
log('c');
// 300ms 후 'c'만 출력됨
```

> 참고: `clearTimeout`은 `null`이나 `undefined`를 넘겨도 에러 없이 무시하므로, `if (timer)` 체크 없이 `clearTimeout(timer)`만 써도 동작은 같다.

### 클로저가 필요한 이유 (정리)
`debounce`가 반환하는 함수는 매번 호출될 때마다 새로 만들어지는 게 아니라 **한 번 생성된 뒤 계속 재사용**된다. 그런데 "이전 타이머를 취소한다"는 동작을 하려면, 여러 번의 호출에 걸쳐 **`timer`라는 상태가 계속 유지**되어야 한다.

만약 클로저가 없다면 `timer`는 함수가 호출될 때마다 새로 초기화되는 지역 변수가 되어, 직전 호출에서 등록한 타이머 ID를 다음 호출에서 알 수 없다. 클로저 덕분에 `timer`가 `debounce(callback, delay)` 실행 시점의 스코프에 "고정"되어, 반환된 함수가 몇 번을 호출되든 같은 `timer` 변수를 계속 읽고 쓸 수 있다 — 즉 **여러 번의 함수 호출 사이에서 상태를 유지하기 위해** 클로저가 필요하다.

## 실무에서 더 고민해볼 지점

### 1. this 바인딩
기본 구현은 함수 인자만 넘기고, 객체 메서드로 쓸 때 `this`는 처리하지 않는다.

```js
const obj = {
  value: 42,
  logValue: debounce(function () {
    console.log(this.value); // 42가 아니라 undefined 출력
  }, 300),
};

obj.logValue();
```

`callback`은 일반 함수인데도 `this`가 `obj`가 되지 않는 이유는 두 가지다.
- `debounce`가 반환하는 함수가 **화살표 함수**라서, `obj.logValue()`로 호출해도 호출 시점의 `this`(`obj`)를 받지 못한다.
- `callback(...args)`처럼 **호출 대상 객체 없이** 호출하므로, `callback` 안의 `this`는 strict 모드에서 `undefined`, 아니면 `window`가 된다. 어느 쪽이든 `this.value`는 `undefined`다.

반환 함수를 일반 `function`으로 바꾸고 `apply`로 `this`를 넘겨주면 해결된다.

```js
function debounce(callback, delay) {
  let timer = null;
  return function (...args) {
    if (timer) clearTimeout(timer);
    timer = setTimeout(() => {
      callback.apply(this, args); // this 컨텍스트 유지
    }, delay);
  };
}
```

### 2. 취소 기능 (cancel)
React 컴포넌트가 언마운트될 때 대기 중인 타이머를 정리하고 싶은 경우 등에 필요하다.

```js
1번의 `this` 처리까지 합친 최종 형태:

```js
function debounce(callback, delay) {
  let timer = null;

  function debounced(...args) {
    clearTimeout(timer);
    timer = setTimeout(() => {
      callback.apply(this, args);
    }, delay);
  }

  debounced.cancel = () => {
    clearTimeout(timer);
    timer = null;
  };

  return debounced;
}
```

React에서 실제로 쓰는 예:
```jsx
function SearchInput() {
  // useMemo로 함수 인스턴스를 한 번만 만들어 렌더링 사이에 유지
  const debouncedSearch = useMemo(() => debounce(search, 300), []);

  useEffect(() => {
    return () => debouncedSearch.cancel(); // 언마운트 시 대기 중인 호출 정리
  }, [debouncedSearch]);

  return <input onChange={(e) => debouncedSearch(e.target.value)} />;
}
```

`useEffect` 안에서 `debounce(search, 300)`을 만들면 그 함수는 effect 안에서만 쓸 수 있어서, 바깥의 `onChange` 핸들러에서 호출할 수 없다. 그래서 `useMemo`(또는 `useRef`)로 컴포넌트 본문에서 한 번만 만들고, effect에서는 정리(cancel)만 담당하게 한다.

## 추가 심화 질문

### Q1. 디바운스와 쓰로틀(Throttle)의 차이는?
- **디바운스**: 연속 호출이 **멈춘 뒤** 마지막 한 번만 실행 → 검색 자동완성, 입력 완료 후 검증
- **쓰로틀**: 연속 호출 중에도 **일정 간격마다 최대 한 번** 실행 → 스크롤 위치 추적, 무한 스크롤, 드래그

```js
function throttle(callback, interval) {
  let lastTime = 0;
  return function (...args) {
    const now = Date.now();
    if (now - lastTime >= interval) {
      lastTime = now;
      callback.apply(this, args);
    }
  };
}
```
스크롤을 계속 하는 동안 디바운스는 한 번도 실행되지 않지만, 쓰로틀은 `interval`마다 실행된다.

### Q2. leading / trailing 옵션이란?
- **trailing** (기본): 연속 호출이 끝난 **뒤**에 실행. 위의 기본 구현이 이 방식.
- **leading**: 첫 호출 **즉시** 실행하고, 이후 `delay` 동안의 호출은 무시. 버튼 중복 클릭 방지처럼 반응은 바로 주되 연타를 막을 때 쓴다.

```js
function debounceLeading(callback, delay) {
  let timer = null;
  return function (...args) {
    if (!timer) callback.apply(this, args); // 첫 호출은 즉시 실행
    clearTimeout(timer);
    timer = setTimeout(() => {
      timer = null; // delay 동안 조용하면 다시 즉시 실행 가능
    }, delay);
  };
}
```
lodash의 `_.debounce(fn, wait, { leading, trailing, maxWait })`가 이 옵션들을 지원한다.

### Q3. React 컴포넌트 본문에서 debounce를 그냥 쓰면 왜 동작하지 않나요?
컴포넌트는 렌더링마다 다시 호출되므로, 본문에서 `debounce(...)`를 호출하면 **렌더링마다 새로운 debounce 함수(= 새로운 `timer` 클로저)**가 만들어진다. 입력할 때마다 state가 바뀌어 리렌더링되면, 새 함수는 이전 타이머를 모르기 때문에 취소할 수 없고 디바운스가 걸리지 않는다.

```jsx
// ❌ 렌더링마다 새 debounce 함수 생성
const onSearch = debounce((q) => fetchResult(q), 300);

// ✅ useMemo(또는 useRef)로 함수 인스턴스를 유지
const onSearch = useMemo(() => debounce((q) => fetchResult(q), 300), []);
```

또는 "값"을 디바운스하는 `useDebounce` 커스텀 훅을 만들 수도 있다.
```jsx
function useDebounce(value, delay) {
  const [debounced, setDebounced] = useState(value);

  useEffect(() => {
    const id = setTimeout(() => setDebounced(value), delay);
    return () => clearTimeout(id); // 값이 바뀌면 이전 타이머 취소
  }, [value, delay]);

  return debounced;
}
```
여기서는 effect cleanup이 `clearTimeout` 역할을 대신한다.

### Q4. 검색 자동완성에서 디바운스만으로 충분한가요?
디바운스는 요청 횟수를 줄여줄 뿐, **응답 순서**를 보장하지 않는다. 먼저 보낸 요청의 응답이 늦게 도착하면 오래된 결과가 화면에 덮어씌워질 수 있다(race condition). `AbortController`로 이전 요청을 취소하거나, 마지막 요청의 결과만 반영하도록 처리해야 한다.

```js
let controller;

const search = debounce(async (keyword) => {
  controller?.abort(); // 이전 요청 취소
  controller = new AbortController();
  const res = await fetch(`/api/search?q=${keyword}`, { signal: controller.signal });
  render(await res.json());
}, 300);
```
