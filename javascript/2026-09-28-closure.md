# 클로저 (Closure)

## 질문
JavaScript의 클로저가 무엇인지 설명하라. 어떤 상황에서 만들어지고 실무에서 어떤 용도로 쓰이는가? React에서 클로저와 관련해 겪을 수 있는 문제(stale closure)는 무엇인가?

## 내 답변 (처음 생각)
- 클로저는 함수가 정의될 때의 변수 환경을 기억하는 기능으로 알고 있음
- useState, useEffect 안에서 만들어진 함수가 특정 시점의 값을 유지하고 변경되지 않는 문제를 stale closure라고 부르는 것으로 기억함
- 지식이 React 위주로 치우쳐 있다고 느낌

## 보완된 개념

### 클로저의 정의
> 클로저는 **함수와, 그 함수가 선언된 렉시컬 환경(Lexical Environment)의 조합**이다. 외부 함수가 이미 종료되어도 내부 함수가 외부 함수의 변수에 접근할 수 있다.

핵심 키워드는 **렉시컬 스코프**다. 스코프는 함수를 *호출한 곳*이 아니라 *작성된 곳*을 기준으로 결정된다.

```js
function makeCounter() {
  let count = 0;
  return () => ++count;
}

const counter = makeCounter(); // makeCounter는 이미 콜스택에서 빠짐
counter(); // 1
counter(); // 2 → count가 살아있음
```

### 클로저는 값을 복사하지 않고 변수(바인딩)를 참조한다
```js
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0); // 3, 3, 3
}
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0); // 0, 1, 2
}
```
- `var`는 변수가 하나뿐이라 모든 콜백이 공유하고, 루프가 끝난 뒤의 값 3이 찍힌다.
- `let`은 반복마다 새 바인딩이 만들어져서 각 콜백이 자기 값을 갖는다.

## Stale Closure (React)

### 왜 생기는가
- React 컴포넌트는 함수라서 **렌더링될 때마다 새로 호출**되고, 그때마다 **새로운 스코프**가 만들어진다.
- `const [count, setCount] = useState(0)`의 `count`는 그 렌더링 안에서는 바뀌지 않는 `const` 값이다.
- 그 렌더링에서 만들어진 이벤트 핸들러나 effect 콜백은 **그 렌더링의 `count`**를 캡처한다.
- deps가 `[]`라 effect가 다시 만들어지지 않으면, 콜백은 첫 렌더링의 `count`(0)를 계속 본다.

```jsx
useEffect(() => {
  const id = setInterval(() => {
    setCount(count + 1); // count가 계속 0 → 결과는 1에서 멈춤
  }, 1000);
  return () => clearInterval(id);
}, []); // deps가 비어 있어서 첫 렌더링의 count만 봄
```

### 해결 방법
```jsx
// 1) 함수형 업데이트 (가장 흔한 해결책)
setCount(c => c + 1);

// 2) deps에 count를 넣어서 effect를 다시 만들기
}, [count]);

// 3) useRef에 최신 값을 담아두고 ref.current로 읽기
```

한국어로는 보통 "stale closure" 그대로 쓴다. 굳이 옮기면 "오래된 값을 참조하는 클로저"다.

## 클로저의 실무 활용

### 1. 데이터 은닉 (private 변수)
외부에서 직접 건드릴 수 없는 상태를 만든다. 위의 `makeCounter`가 대표 예시다. `count`에는 반환된 함수를 통해서만 접근할 수 있다.

### 2. 함수 팩토리 / 커링
설정값을 기억하는 함수를 만들어낸다.
```js
const multiplyBy = (n) => (x) => x * n;

const double = multiplyBy(2);
const triple = multiplyBy(3);

double(5); // 10
triple(5); // 15
```

### 3. 디바운스 / 쓰로틀
타이머 ID를 클로저로 보관해서 호출 사이에 유지한다.
```js
function debounce(fn, delay) {
  let timerId; // 클로저로 보관되는 상태
  return (...args) => {
    clearTimeout(timerId);
    timerId = setTimeout(() => fn(...args), delay);
  };
}

const onSearch = debounce((keyword) => console.log(keyword), 300);
```

### 4. 메모이제이션
캐시 객체를 클로저로 보관한다.
```js
function memoize(fn) {
  const cache = new Map(); // 클로저로 보관되는 캐시
  return (arg) => {
    if (cache.has(arg)) return cache.get(arg);
    const result = fn(arg);
    cache.set(arg, result);
    return result;
  };
}
```

### 5. React 훅
`useState`, `useEffect` 같은 훅이 렌더링마다 값을 "스냅샷"처럼 다루는 방식도 클로저에 기반한다.

## 추가 심화 질문

### Q1. 클로저를 쓰면 메모리 누수가 생기나요?
클로저가 참조하는 변수는 클로저가 살아있는 동안 GC 대상이 되지 않는다. 그래서 큰 객체를 참조하는 클로저를 이벤트 리스너나 타이머에 등록해 두고 해제하지 않으면 메모리가 계속 유지될 수 있다. 실무에서는 `removeEventListener`, `clearInterval`, React의 effect cleanup 함수로 정리해주는 것이 중요하다.

### Q2. var 루프 + setTimeout 문제를 let 없이 해결하려면?
IIFE(즉시 실행 함수)로 반복마다 새 스코프를 만들어 값을 캡처한다.
```js
for (var i = 0; i < 3; i++) {
  ((j) => setTimeout(() => console.log(j), 0))(i); // 0, 1, 2
}
```
