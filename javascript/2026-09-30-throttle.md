# 쓰로틀(Throttle) 구현

## 질문
쓰로틀(throttle) 함수를 직접 구현하라.
- `throttle(fn, interval)` 형태로 호출하면, 연속으로 여러 번 호출되어도 `interval`(ms) 동안 최대 한 번만 `fn`이 실행된다.
- 첫 호출은 즉시 실행된다 (leading edge).
- `fn`에 전달된 인자와 `this` 컨텍스트도 그대로 유지되어야 한다.
- 디바운스와 쓰로틀의 핵심 차이도 설명하라.

## 내 답변 (처음 생각)

```js
function throttle(func, interval) {
  let lastTime = 0;

  return function (...args) {
    const now = Date.now();

    if (now - lastTime >= interval) {
      lastTime = now;
      func.apply(this, args);
    }
  };
}
```

- throttle은 일정 시간 간격으로 함수를 실행하도록 제한
- debounce는 일정시간동안 이벤트가 없을때에만 함수를 실행하도록 제한하는것

## 보완된 개념

### 검증
요구사항 세 가지(leading edge 즉시 실행, interval당 최대 1회, this/args 유지)를 모두 충족한 정확한 구현이다.

```js
const log = throttle((msg) => console.log(msg), 1000);
log('a'); // 즉시 실행 (lastTime=0이라 조건 항상 참)
log('b'); // 1000ms 안이면 무시
log('c'); // 1000ms 안이면 무시
```

### setTimeout 없이 타임스탬프 비교만으로 구현
디바운스는 "타이머를 새로 걸고 이전 타이머를 취소"하는 방식이 필요하지만, 쓰로틀은 "마지막 실행 시각"만 기억하면 된다. 그래서 `setTimeout` 없이 `Date.now()`와 비교만으로 구현 가능하다 — 더 간단하고 타이머 관리 부담이 없다.

### debounce vs throttle (다듬은 버전)
- **디바운스**: 조용해질 때까지 기다렸다가 한 번 실행 (마지막 호출 기준)
- **쓰로틀**: 바쁜 와중에도 일정 간격마다 최대 한 번 실행 (계속 진행 중인 이벤트에 규칙적으로 반응)

## 추가 심화 질문

### Q1. trailing edge도 보장하려면? (직접 작성하지 않음 — 참고용)
지금 구현은 **leading-only**라, `interval` 안에서 마지막으로 들어온 호출은 그냥 버려진다. 실무에서는 leading + trailing을 함께 보장하는 버전도 자주 쓰인다 (예: `lodash.throttle`).

```js
function throttle(func, interval) {
  let lastTime = 0;
  let timer = null;
  let lastArgs = null;
  let lastThis = null;

  return function (...args) {
    const now = Date.now();
    const remaining = interval - (now - lastTime);

    // 매 호출마다 마지막 인자와 this를 갱신
    lastArgs = args;
    lastThis = this;

    if (remaining <= 0) {
      clearTimeout(timer);
      timer = null;
      lastTime = now;
      func.apply(lastThis, lastArgs);
    } else if (!timer) {
      timer = setTimeout(() => {
        lastTime = Date.now();
        timer = null;
        func.apply(lastThis, lastArgs); // 타이머를 건 호출이 아니라 마지막 호출로 실행
      }, remaining);
    }
  };
}

const log = throttle((msg) => console.log(msg), 100);
log('a'); // 즉시 'a'
log('b'); // 타이머 예약
log('c'); // 무시되지만 lastArgs가 'c'로 갱신됨
// 100ms 후 'c'
```

**주의할 함정**: `setTimeout` 콜백에서 그냥 `args`를 쓰면, 타이머를 **건 호출**(위 예시의 `'b'`)의 인자가 클로저에 캡처된다. 그 뒤에 들어온 `'c'`는 `timer`가 이미 있어서 무시되므로, trailing으로 실행되는 건 마지막 호출이 아니라 `'b'`가 된다. 그래서 `lastArgs`/`lastThis`를 바깥 클로저 변수로 두고 매 호출마다 갱신해야 한다.

이건 아직 직접 짜보지 않았으니 참고용으로만 남겨둠. 나중에 여유될 때 직접 구현해볼 것.

### Q2. requestAnimationFrame으로 쓰로틀하는 방법은?
스크롤·리사이즈에 맞춰 화면을 바꾸는 작업은 ms 간격보다 **프레임 단위**로 제한하는 게 자연스럽다. 한 프레임에 한 번만 그리면 되기 때문이다.

```js
function rafThrottle(func) {
  let rafId = null;
  let lastArgs;

  return function (...args) {
    lastArgs = args;
    if (rafId !== null) return; // 이번 프레임에 이미 예약됨

    rafId = requestAnimationFrame(() => {
      rafId = null;
      func.apply(this, lastArgs);
    });
  };
}

window.addEventListener('scroll', rafThrottle(() => {
  header.classList.toggle('shrink', window.scrollY > 100);
}));
```
rAF 콜백은 렌더링 직전에 실행되므로([이벤트 루프 노트](./2026-09-23-event-loop.md) Q2 참고), 화면 갱신 주기(보통 60fps ≈ 16ms)에 맞춰 최대 한 번 실행된다. 백그라운드 탭에서는 rAF가 멈추므로, 화면과 무관한 작업(API 호출 등)에는 시간 기반 쓰로틀이 맞다.

### Q3. Date.now() 대신 performance.now()를 쓰면?
- `Date.now()`: 시스템 시계 기준. 사용자가 시계를 바꾸거나 NTP 동기화가 일어나면 값이 **뒤로 갈 수 있다**.
- `performance.now()`: 페이지 로드 시점부터 흐른 시간. **항상 증가**(monotonic)하고 더 정밀하다.

다만 그대로 바꾸면 함정이 있다. `performance.now()`는 로드 직후 작은 값(예: 50)에서 시작하므로, `lastTime = 0`이면 `now - lastTime >= interval` 조건이 거짓이 되어 **로드 직후 첫 호출이 즉시 실행되지 않는다**. `lastTime`을 `-Infinity`로 초기화하면 해결된다.

```js
let lastTime = -Infinity;
const now = performance.now();
```

### Q4. 실무에서는 어디에 쓰고, 버튼 연타 방지는 쓰로틀과 디바운스 중 뭐가 맞나?
- **쓰로틀**: 무한 스크롤(스크롤 중 주기적으로 바닥 도달 체크), 드래그/마우스 이동 위치 추적, 스크롤 위치에 따른 UI 변경
- **디바운스**: 검색 자동완성, 입력 완료 후 유효성 검사, 리사이즈 끝난 뒤 레이아웃 재계산

**버튼 연타 방지**는 "첫 클릭은 바로 반응하고 이후 연타는 무시"가 목적이라 **leading** 방식이어야 한다. 기본(trailing) 디바운스는 클릭을 멈출 때까지 실행이 미뤄져서 반응이 늦게 느껴진다.
- leading 쓰로틀: `interval`이 지나면 계속 누르고 있어도 다시 실행된다.
- leading 디바운스: 연타가 **멈추고** `delay`가 지나야 다시 실행 가능해진다 → 연타하는 동안 계속 막힌다.

결제·폼 제출처럼 중복 요청이 치명적이면 둘 다 보조 수단이고, 요청 중 버튼을 `disabled` 처리하거나 서버에서 중복을 막는 게 근본적인 방법이다.
